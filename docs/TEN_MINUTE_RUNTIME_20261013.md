# 10分への変更と不要データの整理

2026-10-13の本人依頼に基づく変更。基準はmain `ed4d2cb730b3c9018682e2ff5d8aa5b74890981b`。今回のルール版は `senryou-rules-v2-10min`。

## 一戦の長さと配置

一戦の上限を20分から10分（60回/秒、最大36,000回）へ変更した。画面の残り時間、初期表示、ルール説明、時間ボーナス、検査用の操作履歴上限も同じ上限を使う。最終時刻に敵本拠地の占領が成立した場合は、従来どおり占領を優先する。

| 場所 | 変更前のx / z（m） | 変更後のx / z（m） |
| --- | --- | --- |
| 味方本拠地 HA / 敵本拠地 HB | ±2,400 / 0 | ±1,200 / 0 |
| 前進拠点 P1 / P5 | ±1,400 / 0 | ±700 / 0 |
| 中央の上下拠点 P2 / P4 | 0 / ±900 | 0 / ±450 |
| 中央拠点 P3 | 0 / 0 | 0 / 0 |

拠点の座標を `map-layout.ts` にまとめ、地形・道路・橋・川・建物と初期位置/再出撃位置を追従させた。本拠地間は4,800mから2,400mとなり、前進拠点から敵本拠地までの中央道路は3,800mから1,900mとなる。レーダーの表示範囲も1.2kmにした。道路24m・橋18mの幅、歩兵の占領半径80m、分隊内の間隔、機体寸法、航空回廊同士の間隔は保持する。空域境界は飛行中に旋回できる余白として保持する。

## 整理するデータ

通常の公開ビルドでは、ゲームが使わない検査用の操作履歴と処理時間履歴をためない。開発時の処理時間履歴は直近1,800件だけに制限する。

作戦時間で30秒ごと、および作戦の終了時に、戦闘に参加できなくなった部隊の航空機の補助情報、対空砲の照準情報、砲塔方向、前の位置を整理する。表示側でも30秒ごとに確認し、30秒以上使わなかった部隊の表示を外し、描画用の参照を解放する。再出撃で時計をゼロに戻す際は、表示の最終使用時刻も同じ時計へ戻す。画面が描かれない間の演出待ちデータは4,096件までとする。

得点の台帳、同じ命中を二重に数えない記録、生きている部隊の照準や行動、弾薬、飛行中の弾、出撃予約は必要な情報なので削除しない。形や色のデータは複数の部隊が共用しているため、部隊表示だけを外した時には削除せず、最後に画面全体を閉じる既存の処理で解放する。

`src` / `public` には通信応答を保存するCacheStorageやService Workerの実装がないため、今回整理する対象はゲーム内の一時データである。設定の保存領域や他作品のデータを消す処理は追加していない。

共有している描画資源の扱いは [Three.js公式の解放方法](https://threejs.org/manual/pages/how-to-dispose-of-objects.html) と [描画器の説明](https://threejs.org/docs/pages/WebGLRenderer.html) を確認した。

## 確認

`npm test` は240件成功し、製品ビルドとUI表示検査用の型確認も成功した。10分時点の時間切れ、同時刻の本拠地占領優先、時間ボーナス、停止中の時計、橋の両経路、初期配置と再出撃の安全、10分以内の地上進軍を確認している。不要データの整理では、生きている部隊の情報、得点、重複命中の抑止、共有する形や色を維持する検査を追加した。独立レビューで再出撃時の表示時計の問題を見つけ、修正と再発検査を追加した。

UI表示検査が使う製品コードの指紋を今回のコードへ明示的に更新した。抽出する関数、イベント、識別子、依存、画像と製品コードの一致を確認する既存条件は維持している。

一戦分の自動戦況診断とGitHubのチェック結果は、取得後にこの記録へ追記する。

この確認はiPhoneの実機性能測定ではない。不要データを減らす実装は確認できたが、利用者の端末で報告された重さの原因を特定し、解消を実測したとは扱わない。部隊表示は元から96件まで、演出も固定数までであり、今回の変更で必ず軽くなると断定しない。
